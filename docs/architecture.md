# Architecture

## Core principle

> **AI decides WHAT the world should be. Unity decides HOW to construct it.**

The AI backend never manipulates Unity objects, and Unity never calls an AI
model, the mesh provider or the asset library directly. What crosses the
boundary is a versioned `WorldRecipe` JSON document (see
[`world-recipe.md`](world-recipe.md)) plus, later, the GLB meshes its
`objects[].asset` handles point at — generated by Meshy or retrieved from
Poly Pizza, both proxied by the backend.

## Components

```
┌──────────────────────────────┐  POST /generate-world                     ┌──────────────────────────────────────┐
│   Unity (client)             │  (image + text + sky + personalize)        │   Backend (FastAPI)                   │
│                              │ ─────────────────────────────────────────▶ │                                      │
│  UI (LobbyUI, ImageUploadUI, │                                            │  api/generate_world.py               │
│      GenerationUI, RaceHUD,  │ ◀───────────────────────────────────────── │    VisionService (Claude/mock)       │
│      ResultsUI, ComicStyle)  │  { "world_recipe": {... objects[].asset}}  │    TextAssetService (Claude/mock)    │
│  AI (WorldRecipeClient,      │                                            │    FillerAssetService (Claude/mock)  │
│      MeshAssetClient)        │                                            │    AssetMergeService (Claude/mock)   │
│  Core (GameManager)          │                                            │    object_cropper                    │
│  World (WorldGenerator,      │                                            │    MeshGenerationService ───────────▶│ Meshy image-/text-to-3D
│    TrackGenerator,           │                                            │      (Meshy/mock)                    │
│    EnvironmentGenerator,     │  GET /assets/{task_id}   (poll)            │    LibraryAssetService ─────────────▶│ Poly Pizza search

│    IndoorRoomBuilder)        │ ◀───────────────────────────────────────── │      + MatchPickerService            │
│  Assets (AssetResolver,      │  { "status": "pending|ready|failed" }      │        (Claude/heuristic)            │
```

### Backend

- **api/generate_world.py**: the orchestrator. Runs the vision, filler and
  (personalize only) text-asset Claude calls concurrently, optionally merges
  them, crops and submits meshes, registers every task, and hands
  everything to synthesis. Vision failure fails the request; every other
  stage failing only costs its own objects. See
  `docs/decisions/0012-personalize-toggle.md` and `0014-asset-merge-final-composition.md`.
- **VisionService**: image bytes + description → `SceneUnderstanding`
  (dominant colours, brightness, tags, `mood`, `track_surface`, and
  `detected_objects` with normalised bounding boxes + a `placement` hint).
  `MockVisionService` is the default; `ClaudeVisionService` makes one Claude
  vision call with structured output.
- **TextAssetService** (personalize only): description → key props it
  names that the photo may not show, each with a Meshy text-to-3D prompt —
  `docs/decisions/0007-text-to-3d-key-assets.md`.
- **FillerAssetService**: photo + description → generic library search
  keywords (with placements, up to two landmarks when not personalizing) and
  a theme ground colour — `docs/decisions/0009-generic-filler-from-poly-pizza.md`.
- **AssetMergeService** (personalize only): reconciles the three candidate
  lists into the final landmark/roadside/scattered composition before any
  mesh is submitted; `background` is always filler's own candidate —
  `docs/decisions/0014-asset-merge-final-composition.md`.
- **object_cropper**: cuts each detected object out of the uploaded image as
  a padded PNG crop (degenerate boxes dropped).
- **MeshGenerationService**: crop or text prompt → asynchronous Meshy task.
  `MockMeshGenerationService` (default) issues no tasks;
  `MeshyMeshGenerationService` submits image-to-3D / text-to-3D (hiding the
  preview→refine cycle behind one task), maps status, and downloads/caches
  the GLB.
- **LibraryAssetService** + **MatchPickerService**: filler keyword → Poly
  Pizza search → one chosen hit (a Claude semantic pick by default, or free
  word-overlap scoring) exposed as an immediately-`ready` task; `background`
  keywords get a second distinct match so the wall doesn't repeat one shape
  — `docs/decisions/0011-claude-match-picker.md`. With `sky=indoor` the
  background keyword is forced to `wall`.
- **WorldSynthesisService**: scene + description + all mesh tasks →
  `WorldRecipe`. Still a deterministic keyword mock for name/theme/palette/
  track; `objects[]` is the merged, capped list with `placement`, `source`
  and `asset` handles, `world.mood`/`track.surface` come from vision,
  `world.sky` is the player's preset, and `palette[1]` is filler's ground
  colour when suggested.
- **MeshTaskRegistry**: in-memory `task_id → task` so `/assets` rejects
  unknown IDs (restarting the backend orphans in-flight tasks).

### Unity

- **WorldRecipeClient**: POSTs the single world input (image, description,
  sky, personalize), parses the response into a `WorldRecipe`, or reports an
  error.
- **MeshAssetClient**: polls `GET /assets/{task_id}` and downloads
  `model.glb`. Together with `WorldRecipeClient` this is Unity's entire
  network surface.
- **GameManager**: owns the `GameState` machine and orchestrates UI → backend
  call → world generation → mesh wait → countdown → race → results. On the
  Generating screen it waits for meshes behind `meshWaitTimeoutSeconds`, or
  with no timeout when the player asked for personalized assets.
- **WorldGenerator / TrackGenerator / EnvironmentGenerator /
  ObstacleGenerator**: turn a `WorldRecipe` into the scene — one loop track
  with seed-derived hills and a drop (road ribbon on embankments, barrier
  walls, finish stripe, checkpoints), a placeholder environment composed
  from each object's `placement` hint (landmarks with a glow at key spots,
  roadside lines, a continuous background wall, zoned scattered clusters,
  per-instance variation), boost/stop/spin obstacles reshuffled on the
  racing line, and the sky/fog/lighting/cloud theme from `world.sky` and
  the palette (`IndoorRoomBuilder` replaces the sky with a room for
  `indoor`). All deterministic from `recipe.seed`.
- **AssetResolver**: maps a recipe object to the primitive placeholder to
  spawn now (tuned for known labels, keyword heuristic for anything the
  extractors invent) plus the mesh task that will replace it.
- **GeneratedMeshLoader**: for each mesh task, polls until ready, downloads
  the GLB, imports it once with glTFast, restyles it with the toon shader,
  and places a copy over every placeholder of that type without moving it
  (roadside/scattered copies keep the placeholder's collider). Failure or
  timeout leaves the placeholder.
- **Rendering**: `ToonStyle` (cel shading driven by the palette — ADR 0008),
  `GhibliLook`/`GhibliClouds`/`GhibliPostEffect` (dusty palette, seeded
  clouds, watercolour grade), `PaperGrainEffect` and `SpeedLinesEffect` per
  player camera.
- **Players / Racing / Camera / Audio / UI**: kart physics with obstacle
  effects and cartoon particles/SFX, laps + checkpoints + winner, chase
  cameras with shake and speed zoom, mood-matched music, comic-book lobby
  and upload screens, per-player HUD with obstacle border flashes, results.

## One race, sequence

```
Boot ── Start ──▶ Input ── pick image, type description, pick sky, toggle personalize ──▶ Generating
  │                                                                                          │
  │                                                                     POST /generate-world │
  │                                                                                          ▼
  │                                                  Backend: vision ‖ text ‖ filler (Claude, concurrent)
  │                                                           → merge (personalize) → crops → Meshy submits
  │                                                           → Poly Pizza lookups → WorldRecipe (or error)
  │                                                                                          │
  │                                                         success ─────────┬────── failure │
  │                                                                          ▼               ▼
  │                                                              WorldGenerator.Generate(recipe)
  │                                                              (failure uses DefaultWorldRecipe)
  │                                                                          │
  │                                                                          ▼
  │                                   GeneratedMeshLoader: poll GET /assets/{id} ... ready → GLB → swap
  │                                   Generating screen waits: timeout-bound by default,
  │                                   unbounded when personalize was on; failed → placeholder stays
  │                                                                          │
  │                                                                          ▼
  │                                                       WorldReady ──▶ Countdown ──▶ Racing
  │                                                                                     │
  │                                                          both players finish their laps ─┘
  │                                                                                     ▼
  └──────────────────────────────────────────── Play Again ◀── Results ◀── Finished ◀──┘
```

## Why Unity only talks to the backend

This is a local, same-keyboard 2-player game. There is no online multiplayer,
no matchmaking, and no state synchronization. Unity's whole network surface
is the backend API: the request that fetches the `WorldRecipe`, and the
`/assets` polls/downloads for meshes that request kicked off. Unity never
contacts the vision, mesh or library vendors — see
`docs/decisions/0006-meshy-async-mesh-generation.md` and
`docs/decisions/0009-generic-filler-from-poly-pizza.md`. Anything resembling
network game state is out of scope — see `CLAUDE.md`'s scope checklist.

## Determinism

Every procedural system derives its randomness from `recipe.seed` via
`WorldRandom.DeriveSeed`, never from `UnityEngine.Random`'s global state, so
the same `WorldRecipe` always produces the same track and environment. See
`docs/decisions/0004-seed-derivation.md`. Generated meshes don't affect
layout: they adopt the placeholders' seed-derived transforms, so a world is
laid out identically whether or not its meshes ever arrive.
