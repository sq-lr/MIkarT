# 0008 — Cel-shaded look via a Built-in surface shader

**Decision:** Every renderer in the race world uses one of two hand-written
Built-in-pipeline shaders, `MarioKart/Toon` (stepped lighting + inverted-hull
outline) and `MarioKart/Toon (No Outline)`, both in
`unity/Assets/Resources/Shaders/` and sharing `ToonCommon.cginc`. Runtime
materials are created only through `MarioKart.Rendering.ToonStyle`
(`Assets/Scripts/Rendering/ToonStyle.cs`); the kart and ground `.mat` assets
are re-pointed by `MainSceneBuilder` (**Build Main Scene** or the lighter
**Apply Toon Materials** menu item).

**Why:** The scene mixes three sources that never looked like one world:
flat-colored primitive placeholders, Meshy GLBs imported by glTFast (noisy
textures, baked-in lighting), and the image-picked track surfaces. Quantising
the lighting into three bands hides Meshy's texture noise, makes placeholders
and generated meshes read the same, and is the expected kart-racer style. It
is also cheap enough to render twice per frame for split-screen.

Details worth knowing:

- **Built-in, not URP / Shader Graph.** ADR 0001 keeps the project on the
  Built-in pipeline because URP needs Editor-generated pipeline assets, which
  ADR 0005 rules out hand-authoring. A surface shader with a custom
  `LightingToon` function gets shadows, ambient and forward lighting for free
  and needs no pipeline asset. The outline is an extra `Cull Front` pass that
  pushes back faces out along the view-space normal, scaled by clip `w` so it
  stays a constant screen width. `.meta` files for the shader files are
  generated by the Editor on import, as for scripts.
- **Globals vs. per-material.** Per-object properties (`_Color`, `_MainTex`,
  `_RimStrength`, `_SpecStrength`, `_OutlineColor`, `_OutlineWidth`) live in
  each material. Per-world parameters — `_ToonBands`, `_ToonShadowTint`,
  `_ToonRimColor`, `_ToonRimPower`, `_ToonOutlineInk`, the `_ToonDot*`
  family — are shader globals that `ToonStyle.ApplyPalette` sets once per
  generated world from the recipe: shadow band from `palette[2]` (the same
  entry that tints walls and sky), rim from `palette[0]` (sun). So the AI
  palette visibly shapes the look without walking every material.
- **Shading choices that make it read as drawn rather than dimmed.** Bands
  are split at two thresholds (0.35 / 0.55 on half-Lambert) — a wide lit
  band, a narrow mid band, shadow — instead of equal thirds. The shadow tint
  is pulled up to 0.06 of a turn toward blue-violet, so warm themes get cool
  shadows. Ambient is Trilight (sky/equator/ground around the sky preset's
  ambient) rather than one flat colour. Outlines blend the object's own
  colour darkened with pure ink (`_ToonOutlineInk`, 0.4). Cast shadows are
  thresholded to binary. Karts alone get a hard stepped specular dot
  (`_SpecStrength` 1) on top of full rim; flat surfaces (road, ground,
  horizon fillers) get neither rim nor outline, because a fresnel rim on a
  plane seen at a grazing angle lights up everything beyond a few metres.
- **Comic halftone in the shadows.** `surf` computes a 45°-rotated dot grid
  from `screenPos` (cell size `_ToonDotSize` pixels) and passes it to the
  lighting function through a custom `SurfaceOutputToon.Dot` field. The
  lighting function blends the flat cel bands with an "ink on paper"
  halftone (dot radius grows as the band darkens) by `_ToonDotStrength`, so
  `GameConfig.toonDotStrength = 0` is plain cel shading and `1` is pure
  print dots. Screen-space means the pattern swims across surfaces as the
  camera moves — the standard comic-shader trade-off.
- **Paper grain, not a full-screen halftone.** `PaperGrainEffect` (one per
  player camera, `Hidden/MarioKart/PaperGrain`) multiplies the frame by a
  faint static noise texture built at runtime (`GameConfig.paperGrainStrength`,
  default ±4%; 0 skips the blit). It is intentionally *not* a
  luminance-driven screen halftone: that would put dots over the lit bands,
  sky and particles and stop the shadow-band dots from reading as shading,
  and would cost contrast in the half-height viewports. Grain is sampled in
  screen pixels and never animates, so it reads as paper stock rather than
  film noise.
- **Generated meshes are restyled after import.** `GeneratedMeshLoader`
  calls `ToonStyle.Restyle` on the glTFast template: each material is
  replaced by a toon material carrying over the base colour/texture
  (`baseColorTexture`/`baseColorFactor`, or `_MainTex`/`_Color`). Failure
  leaves the glTFast materials — the swap is never blocked (CLAUDE.md rule 6).
- **Resources/ placement.** Shaders reached only via `Shader.Find` at runtime
  are stripped from builds unless referenced; `Resources/` forces inclusion.
- **Kill switch.** `GameConfig.toonShading = false` makes every `ToonStyle`
  call return the Standard shader, and a missing shader logs one warning and
  does the same. The game looks like it did before, with no code changes.

**Consequence:** The look is uniform but simple: no normal maps, no metallic /
roughness from Meshy's textures (only the base colour map survives). Point
lights would add their own bands per light; there is only the directional sun.

**Revisit when:** Moving to URP (port to Shader Graph, outline as a Renderer
Feature), or when the team wants a full-screen posterise/edge post effect on
top for Meshy textures that the banding alone doesn't tame.
